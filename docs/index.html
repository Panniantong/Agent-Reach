问题

Agent 会写代码、改文档、管项目——但让它去网上找点东西，就抓瞎

每个平台都有自己的门槛：要付费的 API、要绕过的封锁、要登录的账号、要清洗的 HTML。自己一个个踩坑，光是让 Agent 读条推特就得折腾半天。

📖

→ 403，服务器 IP 被拒

设计理念

能力层，不是又一个工具

Agent Reach 比任何具体实现高一层——负责选型、安装、体检、路由，不负责底层读取本身。读取由 Agent 直接调用上游工具完成，没有包装层。

换接入方式 = 调整列表顺序，不是重写代码。agent-reach doctor 会告诉你每个平台当前在用哪个后端，坏掉的会给出修复处方。

每个渠道文件按序真实探测各候选后端（不只是看命令存不存在），第一个完整可用的当选。

channels/
├── web.py      → Jina Reader
├── twitter.py  → twitter-cli ▸ OpenCLI ▸ bird
├── youtube.py  → yt-dlp
├── github.py   → gh CLI
├── bilibili.py → bili-cli ▸ OpenCLI (yt-dlp 已退役)
├── reddit.py   → OpenCLI ▸ rdt-cli (无零配置路径)
├── linkedin.py → mcp-server-linkedin ▸ Jina
└── __init__.py → 渠道注册，doctor 检测用
安全性

凭据只在你本地，改动前先看会做什么

🔒

凭据本地存储

Cookie / Token 只存在 ~/.agent-reach/config.yaml，权限 600，不上传不外传。

🛡️

默认安全

安装默认只检查环境，只有显式 --system 才会写配置、装依赖。

🔍

Dry Run

agent-reach install --dry-run 预览所有操作，不做任何改动。

👀

完全开源

代码透明可审查，依赖的上游工具也全部开源。

免费，开源，随用随体检

所有工具开源、所有 API 免费。唯一可能花钱的是服务器代理（约 $1/月），本地电脑不需要。
